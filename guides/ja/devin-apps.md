# ガイド 10 — Devin Apps：チャットから実働ツールを出荷する

**目標：** 社内ツール、ダッシュボード、ステージングコピーを説明する——Devin が構築し、チームがサインインして開ける安定 URL で提供する。
**レベル：** ここから始める（プラットフォームガイド）· **所要時間：** 最初の App まで約10分
**出典：** [Introducing Devin Apps](https://devin.ai/blog/devin-apps)（2026 年 11 月 13 日）

## 概要

Devin App は Devin のクラウドマシン上に直接ホストされる、実働のプライベート Web アプリケーション。ツールを説明すれば Devin が構築し、チームはリンクから開く——ホスティングもデプロイパイプラインも不要。Devin のマシン*上*で動くので、MCP、インテグレーション、コードベース、自身のデータベース（同じマシン上の SQLite/Postgres）に届き、Devin API 自体も呼べる。

## 作り方

1. サイドバー → **Apps** → App がやるべきことを記述（またはプロンプトテンプレートを選択：メトリクスダッシュボード、プロジェクト状況、レビューキュー）→ **Build with Devin**
2. Devin がセッション内で確認質問をし、構築してオンライン化——Apps ページに URL が表示され、v1 が公開されるまでステータスは `Building`
3. **Share** —— リンクをコピー；指定メンバー、組織、エンタープライズにスコープ。App は決して公開されない；開くには Devin サインインが必要

ブラウザプレビューを生成したセッション内で「publish this as an App」と言うこともできる。

## 更新ループ

- App ページの **Edit in session** → 変更を記述 → Devin が同じ URL に新バージョンを構築。すべての更新はバージョン管理されたデプロイ；新バージョンが起動に失敗しても前バージョンが提供を続ける
- 11 月 25 日以降、Apps は web app の左レールにも表示され、Browser タブの element picker で説明文ではなく視覚要素を直接指せる。
- **自動化で鮮度維持：** 自動化（ガイド 6）を配線し、スケジュールまたはブランチ変更で再デプロイ——毎朝新しいデータを引くダッシュボードが定番の用途

## 動作の仕組み（重要な部分）

- **ハイバネーション：** App はメモリスナップショット上に構築——未使用時はマシンがスリープし、開くと起床（初回ロードに数秒かかることがある）。課金は起きている時間に連動
- **スタック：** ポートで HTTP を提供できるものなら何でも；DB は同じマシンに同居
- **スケールの境界：** 1 台のマシン——社内ツールやダッシュボードには最適、高トラフィックの本番サービスには**不向き**

## 実証済みの 3 つの用途

| 用途 | 例 |
| --- | --- |
| 社内ツール | 管理パネル、申請フォーム、承認キュー——共有スプレッドシートの殺し屋 |
| ダッシュボード | 自社データソースから引くメトリクス/サポート/営業ボード、スケジュール更新 |
| ベータ/ステージングコピー | 実際のスタック（フロントエンド+バックエンド+DB+ワーカー）を Devin のマシンで稼働——チームメイトがリンクからステージングコピーを開く |

## 検証チェックリスト

- [ ] マシンがスリープした後も App が安定 URL で読み込める（数秒のコールドスタートは想定内）
- [ ] Edit in session の変更が同じ URL に新バージョンを生んだ
- [ ] 共有スコープが正しい：アクセス権のないチームメイトがサインインで止められる

## 落とし穴

- **本番トラフィック。** 1 台のマシンでアイドル時にスリープ——ユーザーではなくチームに向ける。
- **静的な考え方。** App の強みは *Devin の環境内に生きる*こと——データ/MCP に配線しなければ、弱い Vercel を作っただけ。

## 理解度チェック

1. Devin App と PR プレビューの違いは？*（App は Devin のマシンから安定 URL で実働配信される——ステートフル、永続、サインインゲート付き。ビルド成果物ではない）*
2. 社内ツールで「チームがサインインして開く」ことが重要な理由は？*（認証が組織から継承される——別途ログインシステムを作り守る必要がない）*
3. どの種類の社内ツールが App に最も合うか？*（「後で完璧」より「今すぐ十分」が勝るダッシュボードとステージング面——メンテコストはほぼゼロ）*
